# Controlled agent comparison

## Freeze the question

Predeclare the task family, acceptance, candidate treatment, baseline, model/host/settings, permissions, time/action limits, repetition count, stopping rule and reviewer rubric. Version the fixture and oracle independently of the plugin being tested. Changing the scaffold and skill together compares their combined effect; label that treatment accurately.

A plain condition and an invoked-astack condition share the same user goal. The invocation and loaded package are the deliberate treatment. Keep neutral project instructions in both. Inspect effective configuration and report residual managed/global instructions that cannot be excluded. Compare pstack directly only under equivalent supported runtime conditions; otherwise it is a design reference or explicitly labelled port.

## Run and retain

Use separate fresh repositories and sessions, one writer per repository. Alternate condition order between repeats to reduce drift. Record all planned attempts before dispatch. Classify activation/setup failure, interrupted or missing result, product failure and passing acceptance separately; retain every attempt. Show pass/planned and the other status counts rather than silently dropping unsuccessful setup.

Use an evaluator outside candidate write scope. Freeze checks before delivery and retain public development checks. Held-out checks exercise supported behavior with unseen inputs, not arbitrary undisclosed product requirements. Check persistence through a fresh authoritative read, ownership through allowed/denied actors and repeat effects through operation identities where applicable. Challenge a material regression with a plausible wrong repair. Verify artifact bytes against their hashes before interpreting them.

Keep full traces and source snapshots in an ignored output directory; retain concise summaries, actual source digests, commands, versions and decisive sanitized artifacts for lasting claims. A schema-valid proof report is a report, not an independent certificate. Isolating files outside write scope does not itself establish adversarial read isolation.

## Review and compare

Give reviewers anonymized source/diff, task intent and the same rubric. Keep candidate mappings, model labels, author claims and acceptance scores separate from initial code assessment. Calibrate on deliberately good and defective examples with human ground truth; measure false passes and useful finding precision. Predeclare the sample/coverage and reviewer qualification rule before seeing candidate grades, including disqualifying missed critical defects/false passes and acceptable useful-finding precision. Insufficient or failed calibration keeps quality unassessed. A reviewer declaring itself independent does not establish independence.

Keep behavioral acceptance, craftsmanship, owner usefulness and delivery effort separate. Require correctness and authorization hard gates. Follow a successful deliverable with a fresh-agent change when maintainability is part of the claim. Record its regression rate and corrective intervention; raw line count is not the grade.

Use repeated matching tasks, report uncertainty and retain model/version changes. A smoke suite localizes failures; broader repeated and held-out tasks are needed for a general promotion claim. Improve one mechanism at a time and rerun the same oracle. A green metadata check, skill read, completed workflow phase or high aggregate score cannot replace product acceptance.
