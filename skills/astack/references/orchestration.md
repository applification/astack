# Run the selected roles

The main agent owns the request, integration and final proof. Read the selected playbook and keep its ordered steps in a proportionate plan. Record skipped steps with reasons and reuse completed work on continuation.

For each substantive contribution, use the playbook's role and read `.astack/models.json` if present. Resolve that role using [model selection](../../setup-astack/references/models.md) and the packaged resolver against the current host catalog. Explicit task choices override saved preferences; do not rewrite them automatically. Missing roles inherit the current model. Unsupported pinned choices stop that contribution with a precise prerequisite; independent work can continue.

An inherited contribution may be done directly. Dispatch every pinned target through the actual host, even when its model matches the parent. Delegate inherited work when parallelism helps or independent review is required. The playbooks’ lead steps stay in the main session and are not configurable model roles. In T3 use `orchestrator_capabilities` and `delegate_task` for cross-provider targets; native delegation is suitable only when it preserves the selected target and host policy. Standalone Claude/Codex use their actual native capabilities. Setup never changes the parent thread's model. Provider settings and persistent modes belong to the host.

Give a child the task, role, selected skill/playbook paths, relevant project guidance, exact checkout/revision, scope, allowed actions, success checks and return format. Assign only its contribution; a linked skill does not expand that brief to the whole playbook. Review contributions are read-only. Do not assume conversation history or that the child loaded the plugin. Keep one writer per worktree; read-only contributions may share the checkout. Every worker returns its actual source changes or findings, checks and remaining gaps.

Retain the host's child/task handle and follow its completion/cancellation API. Avoid duplicate dispatch after a timeout. For T3 review rounds, create a new delegated task with consolidated context and a new request ID; do not continue it by messaging the backing thread. Assess returned work and provider/model identity before integration. A completed child does not complete the parent task.

The lead resolves findings against source and observations, verifies the integrated revision and finishes through [PR guidance](../../pr/SKILL.md) when publication is part of the assignment. A read-only investigation or review ends with its answer. Keep missing proof or independence explicit. Skills do not grant messaging, merge, release or destructive-action authority. Scheduling and durable task records remain host responsibilities.
