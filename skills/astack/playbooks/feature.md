# Feature

For requested guardrail improvements or repeated agent corrections, use [correct](../../correct/SKILL.md) across this sequence: establish evidence in research, choose the owning safeguard in design, implement it with project tools, and review rejection of the bad case and acceptance of valid cases.

1. **research**: Read the affected paths, consumers and existing proof commands. Name the requested behavior and material cases with [implement](../../implement/SKILL.md).
2. **design**: For a consequential interface, state or ownership choice, apply [architect](../../architect/SKILL.md). Use [domain-modeling](../../domain-modeling/SKILL.md) when concepts need sharpening. Compare useful alternatives; record a reason when this step is unnecessary.
3. **implementation**: Use [implement](../../implement/SKILL.md) to deliver coherent slices with project-selected tools. Run the fast checks before dependent work. For a requested hosting transition, use [cloud-transition](../../cloud-transition/SKILL.md) with the selected host and recovery checks.
4. **review**: Apply [code-review](../../code-review/SKILL.md) and [verify](../../verify/SKILL.md) to assess the integrated result against intent and quality. Return findings and proof gaps.
5. **lead**: Resolve findings, recheck affected behavior and finish authorized delivery through [pr](../../pr/SKILL.md).

The lead owns integration. Resolve model roles through [orchestration](../references/orchestration.md); inherited roles may run directly. Preserve the task’s authority and report omitted steps with reasons.
