Reusable engineering skills, lint feedback and loops for coding agents. Your project chooses its stack. astack helps the agent explore open decisions, build the outcome and prove it works. Install the Applification plugin in Codex or Claude Code, then give it a request.

LINT

Feedback in the tools.
Choices in the project.

The base config supplies strict TypeScript feedback. React conventions and portable UI boundaries are explicit opt-ins. Your project owns its runtime, module settings and directory names.

Start with the base

// eslint.config.mjs
import astack from 'astack/eslint';
export default astack();

// tsconfig.json
{ "extends": "astack/tsconfig" }

Install compatible ESLint and TypeScript API dependencies using the README commands ↗. TypeScript 7 compilation can run alongside the API used by lint.

Choose additional checks

import astack, { react, portableUi }
  from 'astack/eslint';

export default [
  ...astack(),
  react(),
  ...portableUi({
    ui: 'views',
    domain: 'model',
    backend: 'server',
  }),
];

react() checks hooks and accessibility. portableUi() checks the boundaries you choose: portable code cannot reach the backend or network, and domain code stays independent of presentation. Neither is enabled by the base config.

Base feedback includes unowned promises, unsafe any access and exhaustive switches. When a rule can be checked mechanically it belongs here. The config ↗ · Behavior checks ↗

LOOPS

The same skills,
without being asked.

A loop is one prompt file that names a trigger and the skills it composes. astack ships no scheduler: run a loop from cron, a CI schedule or your host’s scheduled tasks.

WEEKLYlint-debt

Fixes one lint rule or compiler diagnostic and opens a pull request.

HOURLY OR ON PRpr-review

Reviews open pull requests and reports what the checks showed.

DAILYbug-fix

Reproduces and fixes the oldest eligible bug. Skips a previously blocked report until new reproduction information arrives.

ON A MENTIONmention

Answers the question or makes the requested change.

Run one. With the plugin and lint package installed, pass claude -p < node_modules/astack/loops/lint-debt.md. Plugin-only users copy the chosen prompt from this repository to a local file first.

Bounded. Each run does one slice of work using the project’s chosen tools. It checks for existing work and never merges.

Mentions. Have the trigger append the comment and its thread to the mention prompt.

PROJECT CHOICES

State what is fixed.
Explore what is open.

Early preferences can be wrong for a product. astack brings engineering discipline while leaving technology choices with the project. Explore trade-offs before an open choice becomes a commitment.

A useful first request

Product: a CLI for checking release notes.
Fixed: TypeScript 7, Node 24, pnpm.
Open: module boundaries and config format.
First milestone: read a real config file
and print the parsed release summary.

Explore the open choices and recommend.
Run it to settle observable questions.
Ask about product or preference decisions.

Three kinds of decision

Fixed choices

Accept the selected language, runtime, framework and providers. Load their platform guidance when needed.

Open choices

Compare viable options against the product constraints. Show trade-offs and choose within the authority given.

Observable questions

Run the command, try the integration or inspect the real artifact. Report what happened.

07 / FINISHING THE WORK

Say what passed.
Show what was checked.

Proof names a revision, environment, action and observed result. A later code change calls for a new check when it could affect that result.

CHOOSE THE CHECK

Match evidence to the claim

  • Component story for rendering or interaction states.
  • Focused test for domain or protocol behavior.
  • Running product for data, identity, timing or integration.
  • MCP layers for tool contract, transport and agent choice where applicable.
REPORT THE RESULT

Keep gaps visible

Record pass, fail, inconclusive, skipped or not applicable with a reason. A green exploration job can still be inconclusive when steps fail or budgets expire. Confirm candidates with exact assertions and preserve the first failure when a retry passes.

When proof captures a screenshot or recording, attach it to the PR or link retained media. If no media helps review, say why.

OPEN THE PR

Connect outcome and evidence

The PR states why the work happened, what changed, the affected users or systems, the contract when there is one, and observed results with gaps.

Use the show-me skill ↗ when it clarifies the change. An illustration explains the design; actual observations establish proof. Blocked design, proof or required specialist review stays visible in a draft PR. Investigation alone ends with an answer.
