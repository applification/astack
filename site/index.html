02 / METHOD

The check follows
the claim.

A passing command says what that command checked. astack asks for evidence from the surface where the behavior actually matters.

01 / INTENT

Name the outcome

For a substantial change, keep a short behavior contract in .astack/<feature>/. It ties cases, design choices, and proof together.

Behavior contract ↗
02 / BUILD

Use what helps

For web UI, decide separately whether Pencil and Storybook would answer a real design or component question. Existing projects keep their working stack.

Web UI guidance ↗
03 / PROVE

Observe the product

Run a check that can catch the failure. When integration matters, drive the actual product and record what happened on a named revision and environment.

Proof guidance ↗
04 / REVIEW

Show the evidence

Kept repository changes finish in a PR. The description gives reviewers the outcome, observed result, and any gaps. Investigation ends with an answer.

PR guidance ↗

03 / ADOPTION

Put it to work
in your project.

The installable plugin is called Applification. astack's guidance stays in this repo; your project owns its commands, environments, and product decisions.

TRY IT IN CODEX
codex plugin marketplace add applification/astack
codex plugin add applification@applification

Then start a task with $applification:astack and describe what you want done.

01

Pin it when it matters

For a project-controlled version, point a local marketplace entry at an astack ref or SHA and enable it in that project's Codex config.

Project install guide ↗
02

Keep your stack

Adopting astack does not require a framework or package manager migration. Its Bun, Next.js, and Turborepo layout is the default for new products with no chosen stack.
