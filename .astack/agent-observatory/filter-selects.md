# Categorical filter follow-up

Source `b0269c5` replaces the ten free-text category filters on Runs, Work and Problems with native select menus. Status and work outcome come from the supported domain enums. The other choices come from enrolled project history, independently of result filters and date ranges. A bounded owner-authorized query uses an enrolled/project/time index, reads at most 50 runs and approximately 1 MB per page, and returns deduplicated categorical metadata. The client follows its cursor and shares the catalog across the three pages. No source records or ingestion projections are changed.

Machine choices show names and exact IDs; work references show their label and ID when available. Any removes a category restriction. Existing unavailable drill-down values remain visible until changed or cleared. Dates retain calendar inputs. Clear filters also works when only dates are set. Result pagination automatically passes empty candidate pages until a match is found or the scope is exhausted, preventing a historical choice from producing a premature empty view.

Pen was skipped because native controls reuse the existing layout and visual tokens; there is no new visual direction to resolve. Storybook was selected to exercise choices, loading, empty history and unavailable selections with synthetic data. The original Observatory Pen artifact/comparison gap remains unchanged and PR #20 remains draft.
