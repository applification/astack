# Route journeys and delegated agent branches

An Observatory owner can follow the selected engineering route, expand delegated child journeys, and inspect the captured skills and results that contributed to an explicit parent integration. Agent completion, result delivery, skill reads and successful engineering outcomes remain separate facts.

## Acceptance

- J1: Native Codex delegation and T3-owned tasks retain distinct child identities and lifecycle evidence. Native-first/T3-first capture preserves one canonical run and its original event set while adding identity and delegation metadata. A conversation fork does not establish delegation.
- J2: Route journeys show collapsible child branches with their own captured turns, skills and phase attempts. Siblings using the same phase name and repeated attempts remain separate. Unrecorded, unavailable, failed, cancelled and bounded capture remain explicit.
- J3: A parent integration is an explicit workflow join referencing the child results it used. A spawn tool returning, child completion or host delivery does not create a join. References remain inside the currently enabled, enrolled, readable project/machine capture.
- J4: Evaluation detail resolves delegated child turns through indexed, bounded identity lookups without altering its immutable intent/run snapshot or owner assessments. Child links target the owning run/event. Collapsed branches, expanded evidence and keyboard navigation work on desktop and narrow screens.
- J5: A real parent with two read-only children, distinct skill reads and returned results is normalized through the updated collector and inspected through the running local backend/UI. Synthetic fixtures cover rejection and recovery cases; real traces stay private.

## Design and scope

The owner selected the route journey and agreed the branching concept in this thread. Pen is skipped: the inspected astack site and the approved interactive route/branch prototypes establish the visual direction. Storybook is selected for independent disclosures, sibling/retry isolation, missing capture, explicit joins and responsive evidence navigation. Running local Convex/browser checks cover the actual data adapter; retained screenshots use synthetic fixtures.

This slice adds agent delegation relationships and branch-aware journeys. Explicit skill-to-skill caller instrumentation is deferred. No owner grades, historical skill versions, task success, integration, or exact cross-agent timing are inferred. Runtime deployment is separate from PR delivery.

## Verification

J1–J4 pass domain, collector, native Convex and synthetic browser regressions. J5 passes actual native-first/T3 enrichment, SQLite forwarding, authenticated local Convex detail and desktop/narrow UI inspection with two read-only child tasks. Both returned results resolve at an explicitly recorded parent join; observed reads remain child-owned. The evaluation's single parent run snapshot and owner grades remain unchanged.

Selected synthetic captures and source/environment identities are indexed in [verification evidence](evidence/report.md). Pen remains skipped on the agreed visual direction; exact skill callers, automatic nested expansion and a production rollout remain outside scope.
