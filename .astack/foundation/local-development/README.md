# Local development first and cloud transition

F11 implements the owner's 5 October decision: new apps start locally, and the user decides when to move to cloud. [ADR 0004](../../../docs/adr/0004-local-development-and-cloud-transition.md) records the decision. The [cloud workflow](../../../plugins/applification/skills/astack/references/cloud-transition.md) and generated [reference companion](../../../examples/foundation/.astack/cloud.md) cover target and data choices, frontend/auth/MCP settings, deployment, actual hosted proof and recovery. This iteration implements that workflow; no particular cloud project, host or data transfer was requested or performed.

Ordinary `dev` and `dev:backend` now use persistent account-free local Convex. Startup rejects cloud targets/keys and self-hosted overrides, initializes missing auth settings to disabled/unconfigured values, preserves configured providers, prepares the MCP resource and sets the source build identifier. A private bootstrap process group and an explicit backend-stop wait handle the installed CLI's configure-only and one-off lifecycle. Web and MCP UI use separate fixed ports. Turbo forwards public Vite settings and includes them in build cache keys. Local administration cannot override the target. Shutdown preserves local state; disposable proof remains separate.

The [accepted report](report.json) identifies `unversioned@sha256-e17ce6dcc5204fd67551938a88cdf6382b92509e12a5b5dd6c3fd8e1888706f9`. In a fresh owned copy, `development:verify` observed actual local functions and the served frontend's loopback URL, created an item, stopped the app without deleting its state/configuration, restarted through `dev:backend`, and independently read the same ID/title/status. A configured provider value survived initialization. A private 1483-byte snapshot exported successfully and was deleted with the disposable copy; it is not in the evidence archive. Process enumeration and cleanup completed.

The final workspace gate passed format, typed lint, strict types, 35 tests/553 assertions and three builds in 15681 ms. Root checks passed six tests/24 assertions and all 72 routing cases; package/schema checks and the diff whitespace check passed.

The CLI used an explicit administrative test identity. This proves startup/data persistence and export, not WorkOS login, OAuth, cross-environment data migration or hosted behavior. The cloud workflow requires those observations when a user initiates a real transition. G1/G2 remain explicit provider/installed-host gaps.

Earlier automated attempts remain failed in the [proof archive](local-proof.zip): configure-only backend lifetime/port reuse, missing Turbo environment forwarding, and proof-driver stdout parsing errors. The accepted driver uses raw stdout and tracks detached client descendants during cleanup. An earlier full-check timeout exposed a source-retention regression test that grew with local proof archives; it now checks all source in a clean copy while separate fixture tests cover proof/media retention. Native Pen files are omitted from text sanitization with opaque hashes; they remain editable in the committed design source through Pen MCP. No original trial score or failure was rewritten.

The archive manifest records original/exported hashes, home-prefix and terminal-control transformations; exported entry hashes and deterministic ZIP bytes are verified. It retains accepted/failing reports and terminal logs plus the final workspace/root checks. Public fixture data and marker domains are deliberate; private database/configuration/snapshot bytes are excluded. The archive's checksums identify the exported record, independently of the source identities in each report.
