# Design-aware creation trial rubric v1

Declared before execution; separate from the historical foundation delivery rubric v1 and its six deliveries. Two fresh creation agents use the same committed candidate and selected design, followed by independent read-only reviewers. This exercises design-aware reference generation and proof; it does not establish arbitrary design-to-code synthesis or a new feature/bug trial.

Each delivery and review has a 20-minute deadline and 80-action cap. The configured model/effort are explicit. No recursive delegation, weakened checks, spec changes, production access, publication or messages. Retain candidate/plugin/profile identities, raw events, source, design/readiness observations, screenshots, usage where available and cleanup. Monetary cost is null if unavailable. Report human steering separately from root setup and harness repairs.

Use the existing six 0–2 schema dimensions (maximum 12), with these task-specific criteria:

- **routeIntent:** selects astack foundation creation, reads the design record/spec and actually inspects desktop and narrow exported Pen images before judging conformance; names the selected frame IDs.
- **scopeOwnership:** preserves the selected design and verifiers, shared presentation/data boundaries and local-only authority.
- **supportedImplementation:** generates the pinned reference correctly; trusted nine-frame checks pass for layout, text, type and semantic surfaces, and visual inspection finds no material missing/misplaced content.
- **meaningfulProof:** trusted design verification and R1–R8 running-product acceptance pass for the delivered source; rendered media is inspected against source frames. Fixture rendering and persisted behavior remain distinct claims.
- **recoveryRegression:** addresses actual encountered failures without weakening the acceptance or claiming unobserved recovery. If no defect occurs, a correct bounded verification process earns full credit; do not invent a seeded bug.
- **accurateResult:** final report cites actual evidence, distinguishes reference copying from novel UI synthesis, and leaves live WorkOS/installed ChatGPT gaps explicit.

0 means absent/incorrect; 1 means partial with a material gap; 2 means supported by observations. Pass needs at least 10/12, no zero in meaningfulProof or scopeOwnership, no unresolved authorization defect, and trusted acceptance pass. Reviewers cite files, raw events or images rather than accepting the delivery report alone. Scores are comparable only between these two creation rounds under this rubric.
