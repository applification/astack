# Foundation delivery trial rubric v1

Defined before execution. Two independent rounds use the same profile and tasks, each with a fresh candidate entry and an independent reviewer. Retain the candidate source revision and installed skill digest, profile revision, CLI/model/host versions, prompts, diff, checks, exact running build identity, reviewer evidence and interventions. JSONL usage is retained when available; unavailable monetary cost is null, never estimated as observed.

Tasks: create the supported project; add a useful title-edit feature across web and MCP with persistence and ownership proof; fix a seeded completion mutation defect with a before/after running-product observation and retained regression. The seed is deliberately introduced in the disposable copy, not the reference. Final engineering completion requires the acceptance evidence; the trial does not grant merge or deployment authority.

Each delivery task has a 20-minute elapsed ceiling and 80 action/tool events, and the review has a 20-minute ceiling. Stop a timed-out process, preserve its output and score the incomplete result. No recursive delegation, weakening checks, production writes, messaging or credentials in evidence. These are harness limits, not an owner-approved spending cap. Use the configured model and report it; no silent model substitution.

Score each dimension 0 (absent/incorrect), 1 (partial with material gap), 2 (meets the case with evidence): route/intent; scope and dependency ownership; implementation and supported patterns; meaningful proof; failure recovery/regression; accurate result/gaps. Maximum 12. A pass needs at least 10, no zero in proof or scope, and no unresolved authorization defect. Reviewer cites actual observations; agent self-description alone cannot earn points.

Human intervention is separately reported as none, routine clarification, corrective steering or rescue; count and retain each intervention. Root orchestration/setup and harness repairs are recorded, not hidden. Compare rounds per dimension and note when different prompts, candidate revisions or environments prevent a direct comparison. A pass proves that scenario; repeat observations support future trust.
